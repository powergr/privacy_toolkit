Announcing QRE Privacy Toolkit v2.9.1

Published on October 26, 2026 by The Project QRE Team

QRE Privacy Toolkit v2.9.1 is our largest update since the time-lock. It has a new look, a new file format, safer saving everywhere, and two features that users asked for: a Cancel button for long jobs, and copy and paste that works with Explorer.

This post walks through what changed and why. It also says what the new format does not protect against, because we think that matters as much as the features.

2. A Home Screen You Can See at Once

The Home screen is rebuilt as one screen. All twelve tools are in view with no scrolling, even in a small laptop window. They are grouped as Protect, Inspect, Clean up and Create, each with its own color. A Protection panel shows whether your keychain is backed up, with a Back up now button.

Press Ctrl+K (Cmd+K on a Mac) anywhere to open the jump bar. Type a few letters and press Enter to open a tool or run an action such as Lock now or Back up keychain. It searches names only. It never looks inside your passwords or notes.

The sidebar follows the same groups, and it can shrink to icons with Ctrl+B. On computers, a status bar above every screen shows that the vault is unlocked, a live countdown to the automatic lock, the backup state, and a Lock button.

One flow for every tool

Every tool now follows the same path: a start screen with a drop zone, a progress card while it works, then the result. Success messages appear as a short notice that closes itself. Errors still use a dialog, because they need to be read.

Files and phones

The Files screen gets a Places list, a selection bar, and a Details panel with the type, size, date and location of what you selected. Every part of the address bar is a button, and Ctrl+L lets you type a path.

On a phone, the sidebar becomes a bottom bar with five places: Home, Files, Passwords, Tools and More. Editing panels rise from the bottom as sheets, and touch targets are at least 44 pixels tall.

3. File Format 8

Until now, a locked file kept its header in the clear. Anyone holding the file could read the original file name, such as tax-return-2024.pdf, and the SHA-256 hash of the content. Older formats also had no protection against someone cutting the file at a chunk boundary and rewriting the hash to match.

Format 8 fixes both problems. It is now the format for every new locked file.

Property Formats 5 to 7 Format 8
File name readable without the key YES NO
Plaintext hash readable without the key YES NO
Header fields protected from editing Only some All of them, plus the version and length
A file cut at a chunk boundary is noticed NO YES
Time-lock date can be changed in a hex editor YES NO
A refused unlock rewrites the file Yes, for time-locks Never

The file name and the hash now sit inside an encrypted block. A SHA-256 digest of every other header field is mixed into every chunk, so changing any byte of the header, or moving chunks around, makes the file fail to open. The time-lock date is tied to the sealed binding key, so editing the date no longer opens anything.

Why the ratchet is gone

Version 7 time-locks stored a ratchet in the file: the highest time the app had seen. While reviewing the design, we found that the ratchet could only ever hold a time earlier than the lock date. It never changed whether a file opens. Removing it also means a locked file is never rewritten when an unlock is refused.

Clearer error messages

A damaged header used to look like a wrong password. In format 8 the key check is separate from the rest of the header, so the two cases give different messages. Damage to the key check's own few bytes still looks like a wrong password, and the specification says so.

⚠️
Older apps cannot open format 8 files

Files made by older versions still open and keep their visible names until you lock them again. But a phone or computer that is not updated cannot open a format 8 file. Update every device that shares locked files.

4. Safer Writing and Checking

A file you cannot open is worse than no file. It looks like a backup and is not one. So v2.9.1 changes how every file is written.

  • Verify After Locking: By default, the app opens each new locked file once, the same way unlocking does, before it says the lock is done. If the file is damaged or cut short, it is removed, and the message says your original is untouched. You can switch this off in the options menu.
  • Nothing half-made: A locked file appears under its real name only when it is complete and on disk. An unlocked file appears only after every part and the whole-file hash have been checked.
  • One-step saves: Vault files and a restored keychain go through a temporary file that replaces the old one in a single step. A crash or a full disk can no longer leave a vault empty.
  • Contained output: A damaged or edited locked file can no longer make the app create a file outside the folder you chose.
  • Safer names: Characters that reverse the direction of text, such as U+202E, are replaced. On Windows, names like CON or AUX .txt are refused.
  • Bounded memory: A hostile chunk cannot expand to more than 1 MiB when it is decompressed, and a tampered keychain.json can no longer make the app try to allocate gigabytes.

5. Vault Files Join Format 8

Your passwords, notes, bookmarks and clipboard history are stored in vault files. They used to have their own older container format, with a readable hash of the content and a few unauthenticated header fields. Now they are saved exactly like a locked file.

  • The name inside and the hash of the content are sealed, and the whole header is authenticated.
  • A vault file copied over another one, such as notes over passwords, is refused.
  • Every save is opened again before it replaces the old file, so a bad save cannot destroy a vault.

Vaults from earlier versions move over the first time they are opened. The content is carried over byte for byte. The move only starts after the old file opened with the right key and parsed. If it fails for any reason, the old file stays and the vault opens as before.

🔐
Going back to an older version

After the move, apps older than v2.9.1 cannot open that vault file. If you might go back, copy the four vault files (passwords.qre, notes.qre, bookmarks.qre and clipboard.qre) before the first start of the new version.

6. Cancel a Long Job

While locking a 15 GB folder, we found there was no way to stop it. That was a real gap, and it is closed.

While the app is locking, unlocking, upgrading or time-locking, press Esc or click Cancel on the progress card. The app stops at its next step, which is at most one megabyte of work away. It removes the file it was writing, including the temporary zip of a folder, and it never touches your originals.

Files that were already finished before you stopped stay finished, and the message tells you how many. Copying, moving and deleting cannot be stopped once they have started.

7. Copy and Paste with Explorer

Copy and paste used to work only inside the app. Now Ctrl+C, Ctrl+X and Ctrl+V (and the right-click menu) put the selected files on the Windows clipboard, in the same format Explorer uses. So you can paste them in Explorer, and files you copy in Explorer can be pasted into the open folder in QRE. A cut there is moved.

This works on Windows. On other systems and on Android, copy and paste still work inside the app only. We have not tried the system clipboard on macOS or Linux, so we do not claim it.

8. Upgrading Older Locked Files

Files made by older versions keep their visible names until they are rewritten. There are now three ways to do that, and none of them writes your data to the disk in the clear. Each file is decrypted and sealed again in memory, and the new file is checked from start to finish before it replaces the old one.

  • Upgrade Older Locked Files in the options menu finds the old files in the open folder and its sub folders.
  • Upgrade Format in the right-click menu rewrites just the file you choose.
  • Upgrade Older Files When Unlocking is a setting that is off until you turn it on. It rewrites a file right after you unlock it.

The Details panel now shows a format badge: current format, or an older one with its version number. Files that are still time-locked are skipped until the lock ends. Files locked with a key file need that key file, and USB vault files need their vault unlocked.

9. Smaller Changes Worth Knowing

  • Recovery code notice: Changing your password does not replace the recovery code, so anyone who has seen it can still open your vault. The app now says so and offers a new code in one click. The old code stops working at once.
  • Auto-lock follows the real clock: A phone pauses timers in the background and a computer stops them during sleep. The app now locks at once when you return and the time is up.
  • Plain wording on the time-lock: The dialog and the Help manual now say the lock is kept by the app, not by the encryption. See the limits below.
  • Compression option renamed: The option called Store (None) did not store anything. It is now called Fastest (Minimal), which is what it does.
  • Large files in folders: A single file of 4 GB or more inside a locked folder no longer makes the lock fail, and an unreadable folder no longer leaves a partial zip behind.
  • System Cleaner: Emptying the Recycle Bin, flushing DNS and clearing the clipboard no longer flash a black command window, and a failed Recycle Bin run now reports its reason.
  • Android: The status bar icons are readable in the light theme again, and the top bar in Passwords and Notes no longer scrolls sideways.

10. Built to Be Checked

A security tool should be easy to question. This release comes with FILE_FORMAT.md in the repository, written for outside reviewers. It has the byte layout, the threat model, a table of 18 known limits with their status, a log of every review finding and the decision taken, and the full list of error messages.

It also has two sample files with a known key, and the source of a second program that opens them. We wrote that decoder from the specification alone, without looking at the Rust code. It checks that the document describes the format completely.

The format went through two rounds of outside review. Several findings changed the design: the ratchet was removed, the version and header length were added to the digest, and the error messages were split. Each one is in the review log.

The test suite now has over 840 Rust tests and more than 2,400 frontend tests. For the new code we also broke lines on purpose and checked that a test failed. Where one did not, we wrote the missing test. Each push to GitHub runs a fast subset on Windows, Linux and macOS.

11. Honest Limits

We would rather you know what the app cannot do than find out later.

⚠️
What v2.9.1 does not protect against

The time-lock is advisory. It is kept by the app, not by the encryption. It guards against mistakes and impulse. It does not stop someone who has your master password and the right tools, and the date can be read without the password.

There is no rollback protection. Someone who can write to your folders can put back an older valid copy of a locked file or a vault file, and nothing will notice.

Locking a folder makes a temporary plaintext zip. It sits next to the folder while the lock runs, and it is deleted afterwards, not overwritten. A backup or sync tool watching the folder may copy it.

A key file is hashed once. It is mixed in as a single SHA-256 with no stretching, so use a random file as the key file.

All of these are listed in the known-limits table in FILE_FORMAT.md, with the reasoning for each decision.

12. Before You Update

✅
A short checklist

Back up your keychain from the Home screen.
Copy your four vault files if you may go back to an older version.
Update every device that shares locked files, because older apps cannot open format 8.
Optionally, turn on Upgrade Older Locked Files for the folders that matter most.

QRE Privacy Toolkit v2.9.1 is open source and local-first. It is available for Windows, macOS, Linux and Android.
