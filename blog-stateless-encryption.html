Why We Ditched the Cloud: The Case for Stateless Encryption

Published on December 20, 2025 by The Project QRE Team

When Project QRE began, our architecture looked like every other enterprise security tool: a central server managing keys, heavy infrastructure using HashiCorp Vault, and constant internet connectivity requirements.

It was secure. It was robust. And it was completely wrong for our mission.

The Problem with Cloud Key Management

Cloud-based encryption relies on "The Trust of Others." When you upload a file to a secure cloud service, the keys to unlock that file usually reside on the same infrastructure as the file itself.

This creates three critical vulnerabilities for personal privacy:

  • Single Point of Failure: If the provider shuts down, gets hacked, or is served a warrant, your access to your own data disappears.
  • Telemetry Leakage: Even if the provider can't read your files, they know when you access them, where you are, and how often you decrypt them.
  • Dependency: You cannot access your own tax returns during an internet outage.

The Pivot to Local-First

We realized that to build a tool that truly respects user sovereignty, we had to eliminate the server entirely. We rewrote QRE from scratch using Rust and a Stateless Architecture.

How Stateless Encryption Works

In QRE Locker, there is no database. Instead, we use "Key Wrapping" (similar to a Russian Doll):

  1. The Data Key: A random AES-256 key encrypts your file.
  2. The Wrapper: That Data Key is encrypted by a Kyber-1024 public key.
  3. The Master: The Kyber private key is encrypted by your Password (via Argon2id).

This entire bundle is stored inside the header of the encrypted file itself.

"The lock travels with the box. You hold the only key."

Why This Matters

This architecture means you can put a .qre file on a USB drive and bury it in the desert for 50 years. As long as you remember your password (and have the QRE software), you can unlock it. No server pings, no subscriptions, no cloud validation required.

It shifts the responsibility of security entirely to the user, but in exchange, it offers absolute digital autonomy.
