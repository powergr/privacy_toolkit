A Technical Deep Dive into Our Quantum-Resistant Approach

Abstract / Executive Summary

The advent of fault-tolerant quantum computing poses an existential threat to current public-key cryptography, jeopardizing global data security. This white paper introduces QRE Locker v2.0, a desktop application designed for robust file security in the post-quantum era. Our approach pioneers a defense-in-depth strategy by integrating three core pillars: (1) Hybrid Cipher Techniques, combining AES-256-GCM with NIST-standard ML-KEM-1024 (Kyber); (2) Multi-Factor Key Derivation, which generates strong keys from user passphrases and local keyfiles using Argon2id; and (3) Paranoid Mode Entropy Injection, allowing users to seed the cryptographic process with physical hardware randomness. This paper details the architecture and implementation of QRE Locker, presenting a practical, offline-first solution for long-term data archival.

1. Introduction

The trajectory of quantum computing capabilities signals an urgent need to transition our digital security infrastructures towards quantum-resistant cryptographic solutions. Algorithms like Shor's threaten to break widely deployed public-key cryptosystems such as RSA and ECC. Failure to prepare for this shift could lead to catastrophic breaches of sensitive data archived today ("Harvest Now, Decrypt Later").

Addressing this challenge requires more than just replacing old algorithms; it necessitates a holistic approach to cryptographic design. QRE Locker is an open-source tool engineered to provide such a comprehensive defense. It is founded on the principle of defense-in-depth, leveraging a synergistic combination of established cryptographic primitives and emerging post-quantum standards.

2. The Challenge: The Quantum Threat

For decades, digital security has been underpinned by cryptographic algorithms like RSA and ECC. The security of these algorithms relies on the computational difficulty of certain mathematical problems for classical computers. However, Shor's algorithm running on a sufficiently powerful quantum computer could solve these problems in polynomial time, rendering current encryption vulnerable.

Additionally, Grover's algorithm offers a quadratic speedup for unstructured search problems, effectively halving the security strength of symmetric keys. QRE Locker addresses this by standardizing on AES-256, which retains 128 bits of security even against quantum adversaries.

3. The Proposed Solution: QRE Locker Architecture

QRE Locker is architected as a Stateless, Local-First Application. It does not rely on central servers or cloud key management, ensuring that users retain absolute sovereignty over their data.

3.1 Hybrid Cipher Techniques

We employ a hybrid approach to ensure security against both classical and quantum attacks:

  • Symmetric Layer: The file content is encrypted using AES-256-GCM. A unique, random 256-bit session key is generated for every single file.
  • Post-Quantum Layer: This session key is encapsulated using ML-KEM-1024 (Kyber). The encapsulated key is stored in the file header.

3.2 Advanced Key Derivation (Argon2id)

To protect the private keys used to unlock the file, we use Argon2id, a memory-hard key derivation function. This resists GPU-based brute-force attacks. We support Multi-Factor Authentication by allowing users to combine a Passphrase with a Keyfile (any arbitrary file on their computer). The SHA-256 hash of the keyfile is mixed with the passphrase before derivation, exponentially increasing the search space for an attacker.

3.3 Paranoid Mode (Entropy Injection)

Standard software relies on the Operating System's RNG. In "Paranoid Mode," QRE Locker captures micro-timing events from user hardware interactions (mouse movements, system interrupts) and mixes this entropy into the `ChaCha20` random number generator used to create the encryption keys. This mitigates risks associated with compromised or predictable OS entropy pools.

4. Technical Implementation Overview

QRE Locker v2.0 is built for performance and security using modern systems programming languages.

  • Core Engine: Written in Rust for memory safety and zero-cost abstractions.
  • Cryptography: Uses `pqcrypto-kyber` (FIPS 203 compliant), `aes-gcm` (hardware accelerated), and `argon2`.
  • Memory Security: Implements the `Zeroize` trait to securely wipe sensitive keys from RAM immediately after use.
  • GUI Framework: Built with Tauri v2, providing a lightweight, secure frontend using React/TypeScript while keeping all cryptographic logic isolated in the Rust backend.
  • Compression: Integrates Zstd compression to minimize file size overhead.

5. Security Model

QRE Locker's security model assumes the attacker has full access to the encrypted file but no access to the user's passphrase or keyfile.

  • Confidentiality: Protected by AES-256 and Kyber-1024.
  • Integrity: Protected by GCM authentication tags. Modification of the ciphertext or header is detected instantly.
  • Forward Secrecy: Each file uses a unique ephemeral keypair. Compromise of one file does not decrypt others.

6. Performance

Unlike Python-based prototypes, the Rust implementation achieves near-native performance. By leveraging AES-NI hardware instructions and efficient memory management, QRE Locker can encrypt and decrypt large files (GBs) at speeds limited primarily by disk I/O, with negligible overhead from the post-quantum operations.

7. Future Roadmap

Development is ongoing with a focus on expanding the ecosystem:

  • Mobile Support: Android and iOS applications to allow decryption on the go.
  • Hardware Tokens: Integration with YubiKey/FIDO2 for hardware-backed key derivation.
  • Steganography: Hiding encrypted payloads within other file types.

8. Conclusion

QRE Locker demonstrates that post-quantum security does not need to be complex or slow. By combining state-of-the-art cryptographic research with modern software engineering practices, we provide a tool that is accessible to everyone—from journalists and activists to enterprise archivists—ensuring their data remains secure for decades to come.
